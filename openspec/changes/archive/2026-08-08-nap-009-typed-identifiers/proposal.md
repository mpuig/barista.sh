## Why

Every identifier in the agent is a `String`: `instance_id`, `snapshot_id`,
`op_id`, `idempotency_key`, `guest_token`. In one trait that produces

```rust
async fn delete_snapshot(&self, snapshot_id: &str) -> Result<()>;
async fn remove_orphan(&self, instance_id: &str) -> Result<()>;
```

— same type, opposite meaning, and swapping them at a call site compiles clean.
For a system whose correctness claim is "the right id got journaled", that is the
wrong default, and it is 8k lines of agent relying on the reader noticing.

The guest token is the same problem with a sharper edge. It is a `String` in
`GuestBootstrap`, which derives `Debug`, is handed to every `Runtime::create`
and `start`, and is journaled. Nothing logs it today — nap-007 fixed one leak of
exactly this credential, and the Rust review's `missing_debug_implementations`
pass found a second type where the obvious fix would have reintroduced it. The
class is live; the type system can retire it.

## What Changes

- Newtypes for the five identifiers, generated by one macro: `InstanceId`,
  `SnapshotId`, `OpId`, `IdempotencyKey`, and `Secret` for the guest token.
- Conversion happens **once, at the proto boundary** in `service.rs`. Wire types
  stay `String`, as the contract requires — this is about the 8k lines behind it.
- `Secret` has no `Display`, and a `Debug` that prints `[redacted]`. Its inner
  value comes out only through `expose()`, which makes every real use greppable.
- **No behaviour changes.** Nothing observable over Contract A moves.

## Capabilities

### Modified Capabilities

## Impact

- `crates/nap-node-agent`: `db`, `ops`, `reconcile`, `service`, `runtime` (the
  `Runtime` trait signature), `restore`, `snapshot_key`.
- `crates/nap-guest-agent`: `bootstrap` (the token), `state`, `serve`.
- No proto change, no migration: the journal stores the same strings.

## Constitution Check

- **Schema-first**: unaffected. Newtypes wrap *fields*, not messages; no
  hand-written duplicate of a contract type is introduced, and the generated
  types stay the only contract.
- **Honest capabilities / crash-safe**: untouched — no behaviour changes.
- **Simple by default**: the simpler option is the status quo, and it is
  insufficient for a specific reason rather than a stylistic one: two same-typed
  ids with opposite meanings appear in one trait today, and a credential is a
  `String` in a `Debug`-deriving struct.

## Acceptance

Claims no Phase 1 acceptance test — T1–T12 describe behaviour, and this changes
none. Definition of done: `make check` green with the same test count, and the
five types in use across the agent.

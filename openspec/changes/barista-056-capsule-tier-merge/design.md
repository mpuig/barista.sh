# Design: capsule location strength

Until capsule locations become a separate relation, the single storage field is a monotonic summary. `OBJECT_STORE` dominates `LOCAL_DIR`: repeated registration promotes but never downgrades. The order is a wildcard-free rank function, so a new `CapsuleStorage` variant fails compilation instead of shipping unranked. Registration returns the durable row, and object references are inserted only for a newly created capsule. The RPC therefore reports persisted facts rather than the caller's requested tier.

Promotion makes the input's honesty load-bearing, so the input is verified where the claim is made. Export already earns `OBJECT_STORE` through the upload's read-back-and-re-hash (`commit_remote`). Import claiming `OBJECT_STORE` now earns it the same way for downloads: every manifest object is read out of the bucket and re-hashed (`fetch_remote_verified`) rather than through the local-first `fetch`, whose local hit — on the very node that exported the bytes — proves nothing about durability. An empty or corrupt bucket refuses the import with `CAPSULE_VERIFICATION_FAILED`; refusal, not silent downgrade, keeps degradation explicit.
